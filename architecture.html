Architecture · Personal Assistant (Activepieces)

Two flows, one hub.

One always-on Activepieces container — MIT-licensed, single-container "hobbyist" mode, no separate database to run — hosts two independent flows: email and meetings. Both end at the same Telegram send step.

The wiring

Solid arrows carry data; the dashed arrow is a timer signal, not data. Each lane keeps its color from source to Telegram so you can trace either path with your eye.

Step by step

What actually fires, in order, for each lane.

Email

triggered by: new unread mail

  1. The Gmail trigger polls the Gmail API on a timer, comparing against the last-seen message — so a restart never replays old mail.
  2. A new unread inbox message fires the trigger with the sender, subject, and full body attached.
  3. The OpenAI step is asked for one concrete, concise sentence — not a generic "this email is about" filler.
  4. The Telegram step's message text combines sender + subject + that sentence and sends it.

Meetings

triggered by: the clock, every 5 min

  1. The Schedule trigger fires, rain or shine, every 5 minutes.
  2. It asks the Calendar API for events starting in the next 20 minutes.
  3. A loop steps through each event; a Storage lookup drops any already notified, and a Zoom/meet link is pulled out of each new one.
  4. The Telegram step sends one message per new event, ~10–15 minutes before it starts, then Storage is updated so it's never sent twice.

A third flow: ask on demand

The first two flows only push. This one answers — you message the bot ("what meetings do I have this week?") and it replies, on the same Telegram thread. The part that actually matters here isn't the Q&A, it's the gate in front of it: without it, anyone who finds your bot's username can ask it your calendar.

Where things live

No separate database, no exposed ports, nothing to patch beyond the container image.

Still open

  1. Meeting source. Reading from Google Calendar, on the assumption Zoom invites land there with a join link. If you get Zoom invites that skip your calendar, that needs a second path straight to Zoom's API.
  2. Polling, not push. Simplest self-hosted option — no public HTTPS endpoint required. Real-time push exists but adds real setup for very little gain here.
  3. Notify-only for meetings. The assistant tells you; you add it to your calendar. Auto-creating the event is a small later addition if you want it.
  4. Single user. One bot, one chat ID — you. No multi-user auth, by design.
  5. Summary model. Defaulting to gpt-4o-mini for cost, since this fires on every unread email; every email body it reads leaves the container as an API call to OpenAI. Swappable to a stronger model if summary quality matters more than cost — your call.
  6. Why Activepieces over n8n. Both are free to self-host for personal use; Activepieces' MIT-licensed core and single-container "hobbyist" mode (no Postgres/Redis) made it the lighter pick here.
  7. Q&A scope. Answers are grounded in a fixed 7-day calendar window handed to OpenAI as context — not a true search. Good for "what's coming up"; a "did I get an email about X last month" question needs a real search step added, not just a wider window.
